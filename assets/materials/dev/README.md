# TileEditor development materials

Every `.cymat` in this directory uses the TileEditor-compatible source contract:

```cykv
@cykv 1
@schema "cypher.material" 1
{
    shader = "shaders/tile_surface.cyshader"
    textures = { base_color = "textures/dev/...cytex" }
    parameters = { tint = [1.0, 1.0, 1.0, 1.0] uv_scale = [1.0, 1.0] }
}
```

The current preview adapter accepts exactly that shader, exactly one texture
named `base_color`, and only `tint` and `uv_scale`. Keeping the production kit
inside this contract makes every material discoverable, cookable, and bindable
through **Project Materials** today.

Subdirectories have distinct jobs:

- `blockout/` contains tinted metric-grid variants corresponding to the eight
  built-in blockout roles.
- `diagnostics/` contains identity, repeat, mirror, mip, color-space, scale, and
  fallback probes.
- `semantics/` contains conspicuous authoring labels. They carry no collision,
  trigger, navigation, visibility, audio, lighting, or surface semantics.
- `surfaces/` contains readable level-design surfaces and scale/tint variants.

The top-level `grid`, `brick`, and `hazard` materials remain at their historical
paths because existing maps reference them.

Recipes and the batch manifest are generated by
[`tools/asset_content/generate_tileeditor_dev_recipes.py`](../../../tools/asset_content/generate_tileeditor_dev_recipes.py).
The complete catalog, limitations, provenance, and validation procedure are in
[`docs/TILEEDITOR_DEVELOPMENT_KIT.md`](../../../docs/TILEEDITOR_DEVELOPMENT_KIT.md).
