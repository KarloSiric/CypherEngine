# Renderer resource bindings: bounded OpenGL 4.1 contract

An immutable graphics pipeline declares up to three named GLSL uniform
blocks and up to four named sampled-image uniforms. Each sampled slot
declares either ordinary `sampler2D` (the default) or `sampler2DShadow`.
Bindings occupy consecutive logical slots beginning at zero. The matching
indexed draw supplies one live uniform buffer or texture handle for every
declared slot and leaves every unused slot invalid. A block uses its whole
buffer by default, or an explicit per-draw byte range; the bound span must
be at least as large as the block's reflected byte size and may not be
CPU-mapped.

The OpenGL 4.1 backend maps uniform slot *i* to uniform-buffer binding point
*i*, and texture slot *i* to texture unit *i*. Pipeline creation reflects the
linked shader's active interface: names, exact block sizes, uniform types and
counts must match the declaration. An optimized-out block or sampler is not an
active resource and cannot be declared. The backend sets block and sampler
assignments at each draw because multiple pipelines may share one GL program
with different slot orders.

`R_GetShaderInfo` also returns a copy of the cooked shader's
`interfaceHash`. CYSH V3 derives this identity from its canonical logical
binding interface; older cooked views report the all-zero hash. The value
survives release of the caller's cooked view and lets a future material
binder compare declared interface identities before constructing bindings.
It does not replace the pipeline's live OpenGL reflection checks or bind a
material by itself.

For example, a shader with active `ViewData` and `ObjectData` blocks plus
`base_color` and `detail_color` samplers can use this description:

```cpp
render_pipeline_desc_t pipeline{};
pipeline.shader = shader;
pipeline.vertexLayout = layout;
pipeline.uniformBlockCount = 2;
pipeline.uniformBlocks[0] = { "ViewData", sizeof( view_data_t ) };
pipeline.uniformBlocks[1] = { "ObjectData", sizeof( object_data_t ) };
pipeline.sampledTextureCount = 2;
pipeline.sampledTextures[0].name = "base_color";
pipeline.sampledTextures[1].name = "detail_color";

render_draw_indexed_desc_t draw{};
draw.pipeline = pipelineHandle;
draw.vertexInput = vertexInput;
draw.uniformBuffers[0] = viewBuffer;
draw.uniformBuffers[1] = objectBuffer;
draw.sampledTextures[0] = baseTexture;
draw.sampledTextures[1] = detailTexture;
draw.indexCount = indexCount;
draw.vertexCount = vertexCount;
```

The frontend rejects missing, extra, stale, mapped, wrongly typed, and
undersized resources before backend submission. It also rejects sampling
either attachment of the active render target in either slot. A failed
validation or backend draw releases any temporary uniform-buffer references.

For many objects, pack their uniform records into one buffer and select a
record per draw with `draw.uniformRanges[slot] = { offset, byteSize }`.
`{0,0}` keeps the original whole-buffer binding. An explicit range needs a
positive size covering the pipeline's reflected block and an offset divisible
by `R_GetInfo()->limits.uniformBufferOffsetAlignment`; the complete span must
fit the buffer and the native signed address range. The OpenGL 4.1 backend
uses `glBindBufferRange` for a slice and `glBindBufferBase` for the default.
Hosted frames restore the application's prior indexed uniform-buffer ranges.
This avoids rewriting the same transform buffer before each draw, but draw
submission and resource ownership remain immediate.

## Sampling policy

A draw may optionally pair each declared texture slot with an immutable
`render_sampler_handle_t`. Its description selects nearest or linear minification
and magnification, no/nearest/linear mip filtering, and repeat or edge-clamp
addressing independently for U and V. This lets one image be reused with
different sampling policies in the two slots. An invalid sampler in a declared
slot keeps that texture's existing creation-time filter and wrap settings;
existing draws therefore need no sampler changes. A sampler in an undeclared
texture slot is a binding mismatch. A mip-filtered sampler needs a complete
mip chain, either generated by the backend or supplied by a cooked texture.
Ordinary render-target textures do not provide that chain.
This includes D24 target depth: it has one mip level and can be read by a
scalar `sampler2D` after its target pass ends. The shader reads depth from the
sample's red component. For hardware depth comparison, declare that pipeline
slot as `DEPTH_COMPARE_2D`, use an active `sampler2DShadow` uniform, and bind
a D24 texture with an explicit sampler whose `compare` is, for example,
`LESS_EQUAL`. A shadow slot rejects a color texture, an omitted sampler, or a
sampler with `compare = NONE`. A scalar slot rejects a comparison sampler.
These checks prevent undefined OpenGL shader/sampler combinations. The D24
texture itself retains ordinary scalar sampling as its default; the explicit
sampler supplies comparison behavior for that draw. Nearest filtering gives a
single comparison; the exact filtering of multiple depth comparisons with
linear sampling is implementation-dependent.

Sampler handles are generational renderer objects, independent of texture
handles. Draws resolve them immediately on the renderer thread; neither object
retains the other. The OpenGL 4.1 backend binds an explicit sampler object on
the corresponding texture unit, or binds sampler zero for the legacy policy.
Hosted frames restore the host's sampler bindings for both used units.

This is a binding contract, not a general material system. A narrow cooked
material adoption layer is described below. Anisotropy, arrays, cubemaps,
storage buffers, ordinary uniforms, more than two slots, and reusable draw
queues remain separate work.
The hosted frame preserves both slots of borrowed OpenGL texture, sampler, and
indexed uniform-buffer state. It currently queries this state each frame; its
effect on editor frame time still needs measurement.

## Adopting a cooked texture

`R_CreateTexture2DFromCooked` is the first direct bridge from a validated CYTX
file to a renderer texture handle. Keep the cooked file bytes alive and
unchanged for the call. The function reparses them, verifies that the supplied
view still describes that file, and synchronously uploads each resident level;
the renderer retains neither the view nor its borrowed bytes. The returned
handle follows the ordinary `R_DestroyTexture` lifetime rules.

For a runtime-owned file, acquire the texture's typed resource handle, call
`Res_GetCookedTexture`, upload that borrowed view, then release the resource
handle. The GPU texture remains valid because creation consumed the pixels
before returning. A focused resource-to-renderer test exercises that ownership
boundary, including an upload failure and retry. No automatic GPU cache or
material dependency tracking is implied by this handoff.

For now the texture adoption path accepts fully resident, tightly packed 2D color images
with one frame, layer, and face, in linear/sRGB RGBA8 or linear RGBA32_FLOAT.
It also accepts a cooked `NORMAL` image only when it is linear RGBA8_UNORM;
OpenGL uploads its encoded tangent-space channels without sRGB conversion.
It accepts a single level or an authored mip chain reaching 1×1. The backend
consumes the authored pixels without regenerating them;
`render_texture_info_t` reports both the level count and whether the chain is
complete. RGBA32_FLOAT uses 16 little-endian bytes per texel and requires a
little-endian host for direct upload. The OpenGL 4.1 backend stores it as
`GL_RGBA32F` and samples it without clipping values above 1.0. Direct
`R_CreateTexture2D` uploads also accept native RGBA32F pixels and may generate
mips, but RGBA32F is linear and sampled-only; RGBA16F remains the offscreen
HDR target format. OpenGL neutralizes and restores the host's pixel-unpack
buffer, row layout, and byte-swap state during either float upload.

A valid CYTX file using compression, streaming, an incomplete multi-level
chain, 3D storage, or another pixel format returns
`ERR_RESOURCE_FORMAT_UNSUPPORTED`. Invalid or modified views and file bytes
return `ERR_INVALID_ARGUMENT`. A backend without authored-level upload returns
`ERR_UNSUPPORTED`. Compatible float images can also be adopted by the limited
cooked-material bridge described below. Cubemaps, streaming, and wider material
binding remain separate work.

## Adopting a cooked material subset

`Cypher::RenderMaterialRuntime` sits above the renderer and resource loader. A
caller passes a normalized cooked `.cymat_c` path, a vertex layout, and any
shader uniform-block declarations to `R_CreateCookedMaterialBundle`. The bridge
acquires the CYMT material and its referenced CYSH/CYTX files through
`CypherResource`, compares the material's interface hash with the shader's CYSH
V3 identity, and validates each texture name and logical binding ID. It loads
all dependencies before creating GPU objects. Creation then builds a shader,
textures, and a pipeline, releases the CPU resource handles, and publishes one
caller-owned bundle. `R_ApplyCookedMaterialBundleToDraw` copies its pipeline
and texture slots into a draw record, plus the owned material uniform buffer
when present; the caller supplies geometry, view/model uniforms, and frame
state. `R_DestroyCookedMaterialBundle` releases the pipeline before its shader,
followed by independent textures and its optional material uniform buffer.

For a hand-built cooked shader that actively declares a separate
`sampler2DShadow`, the optional `passShadowMapBinding` names a caller-owned
shadow-map binding. This bounded path requires exactly one material-owned
albedo texture in slot 0; it reserves slot 1 for a D24 render-target texture
and an explicit comparison sampler supplied in each draw. Creation checks the
cooked binding and OpenGL pipeline reflection, but neither acquires nor owns
the pass texture or sampler. Apply validates the live pair and preserves it;
the host keeps both alive through drawing and avoids sampling a target while
that target is being written. An ordinary bundle still clears unused draw
sampler slots. An opt-in 320-byte World lighting View record now carries the
light-space matrix, but the host still owns its upload and pass order. The
authored shader cooker cannot yet produce this depth-sampler binding.

This first bridge accepts CYMT V2 opaque, mask, blend, or additive surface
materials with the default empty feature variant, no named
surface, identity UV transforms, and no authored sampler preset. It supports zero to
two fully resident 2D color textures in linear/sRGB RGBA8 or linear
RGBA32_FLOAT, with one or a complete authored mip chain. The normal-map
variant below uses one color and one NORMAL texture. Float DATA textures and
streamed mip tails remain unsupported and are rejected before GPU creation.
Both textures normally use UV0. An opaque static surface may instead put a
linear RGBA8_UNORM or RGBA32_FLOAT lightmap in material slot 1 with UV set 1,
while slot 0 remains UV0 albedo. Its vertex layout must declare RG32_FLOAT at
location 3 on binding 0, and its shader must read that attribute and use it
for the slot-1 sampler. The bridge checks the cooked UV declaration, layout,
and linear lightmap format before creating GPU objects, but cannot infer
which UV a shader actually samples. A native World camera pixel test checks
one compatible hand-built cooked shader: fixed UV0 albedo and independent
UV1 lighting give visibly different pixels. This is a supplied lightmap,
not a lightmap baker or a directional-normal lightmap. The cooked-material
subset still declares at most two owned textures, and its optional pass
shadow binding is fixed at slot 1; this lightmap recipe cannot combine with
that shadow binding yet.
Another opaque two-texture variant keeps COLOR albedo in slot 0 and binds a
linear RGBA8_UNORM `NORMAL` texture in slot 1, both using UV0. The layout must
also expose an RGBA32_FLOAT tangent with handedness at location 4 on binding
0. The bridge validates usage, format, UV, and layout before GPU creation;
the hand-built shader must decode the sampled tangent-space vector and
construct its tangent basis, including mirrored-model handedness. A native
World camera pixel test checks that opposite +Y/-Y normal texels change
directional diffuse with constant albedo, including after mirroring the
World object. The bridge cannot prove shader semantics, and its current
recipes cannot combine this slot-1 normal map with a lightmap or pass shadow.
The first supported material value is one F32X4 `tint` at byte offset zero.
The cooked shader must declare a matching MATERIAL VALUE and a 16-byte
MATERIAL uniform block named `Material`, whose GLSL std140 member is
`vec4 tint`. For this subset the caller declares `View` at uniform slot 0,
`Model` at slot 1 (a 64-byte `mat4`, an 80-byte `mat4` plus cutoff `vec4`, a
112-byte `mat4` plus std140-padded inverse-transpose `mat3`, or a 128-byte
record with both normal matrix and cutoff), and `Material` at slot 2. The
bridge packs the
decoded value into native float bytes, creates and owns the slot-2 buffer,
and binds it per draw. The exact member name and offset are an authoring
convention: native pipeline reflection verifies the block's size, not its
member layout. Other value types and Model block sizes fail preflight for this
tint path.
The 80- and 128-byte variants match the World camera adapter's opt-in cutout
records; the shader must use the cutoff and discard sampled alpha for `MASK`.
The current authored shader cooker does not yet emit these uniform-block
bindings, so these layouts require a compatible hand-built cooked shader.
All shader resource bindings must fit those texture slots or the caller's
declared uniform blocks. A two-sided material disables back-face culling; its
casts-shadows flag is consumed by the World light-view adapter. The
bundle owns ordinary and winding-reversed graphics pipelines that share one
shader. The second pipeline flips only the front-face sense; culling, depth, and blend
policy stay the same. It is used for a negative-determinant model transform,
including when a two-sided shader uses `gl_FrontFacing`. Both pipelines must
be destroyed before the shader can be released. The bundle preserves the
cooked alpha mode and cutoff: `BLEND` creates a depth-tested pipeline with
straight-alpha blending and no depth writes. Its shader must emit straight
(unassociated) color and alpha. The caller must draw it after opaque surfaces
and sort translucent objects back-to-front; the bridge does not classify or
sort scene draws. `MASK` uses opaque depth writes and no blending. The World
camera adapter can place the copied cutoff in an opt-in 80- or 128-byte Model
record and requires a scalar RGBA alpha source at sampled slot zero. The
light-view shadow adapter separately uses an 80-byte Model record, the same
slot-zero alpha source, and a caller-owned depth-only cutout pipeline. Other
callers pass the cutoff through their own uniform block. Matching color and shadow shaders
must discard sampled alpha below it. The bridge cannot verify shader discard
semantics. `ADDITIVE`
creates a depth-tested pipeline without depth writes. It adds
`source.rgb * source.a` to destination RGB while preserving destination alpha.
The caller draws it after opaque geometry; the bridge does not schedule it.
Unsupported material data returns `MATERIAL_UNSUPPORTED` instead of being dropped. A
shader hash or binding mismatch returns `SHADER_INTERFACE_MISMATCH` before any
GPU object is created.

If GPU creation fails, the bridge unwinds the objects it created and normally
leaves the output empty. If a backend destruction call itself fails, it returns
`CLEANUP_FAILED` with the still-live handles in the bundle so the caller can
retry destruction before renderer shutdown. This retry applies to successfully
created renderer handles. A failed backend Create that returns a native token
still relies on immediate native-token cleanup; if that destroy also fails,
the renderer frontend cannot publish the token for retry. The OpenGL backend
cleans its own partial pipeline creation before returning an error. This is
synchronous adoption, not
a cache, material hot reload, asset dependency residency manager, or complete
CYMT feature implementation.

The hidden-window OpenGL smoke generates compatible materials, a shader, and
textures in memory, loads them through the VFS and resource manager, releases
their CPU handles, and verifies the RGBA8 image with a framebuffer pixel read.
A second draw adopts a cooked RGBA32_FLOAT albedo through the material bridge,
samples a red value of 4.0 into an RGBA16F target, and reads it back without
clipping. Its geometry comes from the validated static-mesh upload bundle and
an active World submission. A third draw verifies that cooked
`{4, 0.5, 0.25, 1}` albedo multiplied by cooked `{0.25, 0.5, 0.75, 1}` tint
reaches the HDR target as approximately `{1, 0.25, 0.1875, 1}`. These tests
prove the narrow bridges reach real OpenGL 4.1 draws. Checked-in authored
`.cymat` and `.cyshader` recipes still use schema V1 and do not yet produce
the CYMT V2/CYSH V3 pair or `Material` UBO required by this bridge.

## Native creation failure ownership

The OpenGL backend cleans up a partially created buffer, vertex input, or
pipeline and leaves its output token invalid when creation fails. The backend
contract permits a nonzero token on error only if its matching destroy callback
can retire that token. The renderer frontend defensively calls that destroy
callback before returning the creation error. For a vertex input it does so
before releasing retained buffers; for a pipeline it does so before releasing
the shader. No public handle is published on failure. A backend that reports a
destruction error for a failed creation still violates the stronger cleanup
expectation; this fallback does not provide a retryable public handle.
