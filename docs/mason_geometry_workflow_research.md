# Mason geometry workflow research

Reviewed 2026-10-03. Scope: geometry authoring and viewport input; preserve Mason's accepted layout and theme. This is a reference matrix, not a claim that every listed operation is implemented in Mason.

## Camera and input ownership

Hammer documents right-button + WASD navigation, `Alt+LMB` orbit, `Shift+A` reset orbit center, `Alt+RMB` zoom, `Alt+MMB` camera look, F2/F3/F4 Top/Front/Side, and `Ctrl+Space` cycling 2D views. Its current active viewport requires a mouse-button press. The documentation explicitly says Z fly mode does not work in CS2 Hammer. See [Valve Navigation](https://developer.valvesoftware.com/wiki/Source_2_Docs/Level_Design/Navigation).

Mason deliberately keeps the user's hover activation preference. Text fields, menus and modal dialogs must retain focus. During camera flight, held movement inputs outrank editing shortcuts: `E` cannot both move upward and select Scale. Outside flight, tool bindings should remain immediate. Dispatch precedence should be active tool → viewport family → viewport → map → global. Selection-mode contexts will also be needed before conflicting component commands are enabled.

The current viewport dispatcher handles one-stroke bindings through the shared command registry. Its preflight reserves disabled or unknown bindings and explicitly unbound inherited chords, preventing a different window shortcut from capturing the same key. Multi-stroke global QAction shortcuts retain their existing behavior; tool-specific multi-stroke input needs per-view sequence state, timeout and cancellation before it can be advertised as supported.

### Current Mason shortcuts and gesture ownership

These are the implemented Mason defaults, including deliberate convenience bindings; they are not an assertion of exact Hammer parity.

| Action | Current binding | Behavior and scope |
| --- | --- | --- |
| Select / create / clip | `Shift+S`, `Shift+B`, `Shift+X` | Select the available tool; repeating the effective Clip command cycles Back → Front → Both → Back while retaining the staged plane. |
| Translate / rotate / scale | `T`, `R`, `E` | Shared map commands; configured camera flight keys retain priority during navigation. |
| Brush face push/pull | `X` | Mason convenience binding for the existing convex brush-plane operation; it does not create mesh topology. |
| Texture tool / apply material | `Shift+A`, `Shift+T` | Material apply is eligible only with an editable authored brush face selected. |
| Inspect object | `Alt+Enter` | Opens the working generic inspector; the future entity-specific properties command remains unbound and unavailable. |
| Convex brush merge | `Ctrl+Shift+M` | Merges exactly two compatible visible brushes into their actual convex union; the existing Mason shortcut remains unchanged. |
| Smaller grid | `[`, `-`, keypad subtract | Runs the existing live grid command, bounded at the minimum. |
| Larger grid | `]`, `+`, keypad add | Supports both shifted and unshifted Plus events; runs the existing live grid command, bounded at the maximum. |
| Confirm / cancel active gesture | `Enter` or keypad Enter / `Escape` | The view owns commit or rollback. It consumes the effective logical binding before normal command dispatch. |
| Orthographic nudge / fine nudge | Arrows / `Shift` + arrows | Move editable whole Objects/Groups along the active projection axes by the authored grid size / one world unit; one undo step per keypress. |
| Active-pane preview modes | `F5`, `F6`, `F7` | Fullbright material colour, fixed directional Shaded preview, and Normals diagnostic. These do not evaluate authored lights or replace the runtime renderer. |
| Active-pane overlays | `F8`, `F11` | Toggle wire overlay / mesh face edges. Geometric viewport F11 takes priority over window fullscreen. |
| Focus next visible pane | `Tab` | Mason convenience; skips hidden panes and leaves a maximized/single pane unchanged. Embedded editors retain native Tab traversal. |

`MapInput_ToolGestureKey` uses the same tool → viewport family → viewport → map → global lookup as command dispatch, including user remaps, platform overlays and explicit unbinding shadows. A more-specific disabled or unrelated binding prevents a lower-context confirm/cancel from firing. The helper itself executes no command; view-owned idle cancellation is described in the later Select workflow checkpoint. Tests exercise changed shortcuts as well as defaults, so an active gesture does not retain an unconditional Escape fallback after a user remaps Cancel.

Plus is a named key in `.cykeymap` (`Plus` or `Shift+Plus`), avoiding ambiguous modifier-separated strings such as `Ctrl++`. Keypad Add/Subtract remain distinct keys. An Equal event is not reinterpreted as Plus, and Ctrl/Command+Plus is not the grid shortcut. The existing four-chord-per-command limit accommodates bracket, unshifted Plus, shifted Plus and keypad Add without changing the format.

## TrenchBroom behavior worth adopting

The official TrenchBroom manual fetched on 2026-10-03 identifies itself as **2026.2** and describes hover-following viewport focus, linked 2D axis panning/zoom, and cursor-anchored wheel zoom. Its brush extrusion uses `Shift` + face drag along the face normal; `Ctrl` at drag start splits an extruded brush. `Alt` controls vertical object movement, not this face-resize gesture; this corrects the earlier modifier note. `Esc` cancels a drag before canceling its tool/selection. Selection drilling uses `Ctrl` + wheel. One mouse drag is one undo transaction. Convex merge is `Ctrl+J`, subtract `Ctrl+K`, hollow `Ctrl+Shift+K`, intersection `Ctrl+L`. These version-specific keys differ from Hammer and Mason; use behavior as inspiration without silently replacing existing Shift-add/clone or camera bindings. See the [official TrenchBroom 2026.2 manual](https://trenchbroom.github.io/manual/latest/index.html#extrusion).

## Evidence limitations and follow-up

### Integrated authoring pass, 2026-10-03

This is an earlier checkpoint. Its Block release-to-create rule is superseded by **Staged Block construction and RGB size controls** below; other supported operations remain unchanged by that increment.

The accepted main window layout and theme are preserved. The current authoring routes are:

- Convex box, wedge, cylinder, spike/cone and sphere creation by dragging a footprint in a 2D view or on the world XY plane in 3D. Release or the configured Confirm key commits; Cancel or focus loss rolls back. Tool Properties also exposes exact numeric bounds, omitted-axis depth, primitive axis, cylinder/cone side count, cone top-radius ratio and supported sphere subdivisions. Live preview shows dimensions, and Shift+wheel adjusts gesture depth. Every pane draws the actual generated primitive, with a separate construction envelope. Round tessellated shapes fit that envelope without promising to touch each envelope face. Arches are not exposed as a working single-brush primitive.
- New primitive faces receive the active material and the configured world UV repeat density. Mason maps `editor.map.default_texture_scale` to `512 × scale` world units per repeat, preserving 128 units at the 0.25 default. This is an explicit editor mapping; it does not infer source texture resolution or claim a per-texel scale.
- Select in Objects/Groups supports direct movement with visible RGB axis, planar and center handles, or a plain drag on selected geometry. Plain body dragging retains multiselection; Ctrl/Command body clicks toggle and Shift body clicks add. Object translate, rotate and positive scale have world-axis gizmos in 3D and the applicable axes in 2D; scale includes planar and uniform center handles. T/R/E selects the explicit tools. Shift+translate drag clones with fresh identities; Ctrl temporarily bypasses snapping. Numeric controls and the Transform Selection dialog provide precise values and a selection-center/world-origin pivot. Texture lock governs translation/rotation; the independent Texture Scale Lock setting governs stretching UVs during scale.
- Authored convex brush-face picking in 3D, or explicit persistent-side selection in Tool Properties. Push/pull moves that face's plane and validates the resulting solid. This is a brush-plane resize, not a topology-creating mesh extrusion. Active material assignment changes the selected face while preserving its UV projection. The rendered push/pull shaft and end cap are directly draggable, including outside the brush silhouette.
- Brush clipping supports Back (`n·p+d ≤ 0`), Front (`n·p+d ≥ 0`) and Both. Drag a snapped line in Top/Front/Side to stage a plane extruded along the omitted axis; Ctrl/Command bypasses snapping. Release keeps the actual retained brush geometry visible in all panes. Confirm publishes one batch edit; Cancel discards it. Repeating the effective Clip shortcut cycles retained halves without moving the plane or editing the document. Released planes survive focus changes so Tool Properties and 3D inspection remain usable; focus loss during an unreleased drag cancels it. Numeric plane fields reflect a new staged plane and can apply precise values with the same Retain mode. Clip guides have two editable world-space endpoints, shared across compatible 2D panes and the 3D view. Direct 3D placement uses an explicit X/Y/Z construction plane through the selection center, with the cutting line extruded along that axis. Endpoint grabs retain the pointer offset, snap only the two editable coordinates, and preserve the captured construction depth. Arbitrary surface workplanes and three-point clipping remain unavailable. New cut faces use the active material captured by the shown preview and independent planar UVs; inherited faces retain their authored material and UV projection. Wholly discarded brushes are removed; unsplit Both and wholly retained results preserve identities and produce no history. Productive Both creates fresh root and side identities for both halves while preserving layer, entity ownership, root metadata and exact side residual ancestry.
- Hollow replaces a brush with valid convex wall fragments at the chosen thickness. Backend side provenance transfers source materials, UVs and residual face metadata. Layer and entity ownership survive.
- Brush subtraction uses `MapBrushEdit_Subtract` through `MapWorkspace_SubtractBrush`. Selected brushes are the targets; the user explicitly picks a visible brush outside that selection as the cutter. The cutter is retained. Disjoint or touching targets keep their identities, contained targets disappear, and productive cuts replace targets with fresh convex fragments. Root metadata, layer and entity ownership follow the targets; face materials, UVs and residual fields follow their actual target or cutter ancestors. The Select and Block Tool Properties contain a collapsed Brush subtraction section with the cutter picker and apply action. The main layout and toolbar remain unchanged. The batch prepares and validates its complete result before one history entry publishes it; an all-no-op batch adds no history.
- Convex brush Merge uses `MapBrushEdit_Merge` through the existing `map.brush.merge` command and `Ctrl+Shift+M` binding. Exactly two visible authored brushes must have explicit matching layer and entity ownership. Their actual union must be convex; the adapter rejects disjoint gaps and concave pairs rather than filling them with a hull. The result has fresh root/side identities and one undo step; undo restores both originals and their selection. The lowest selected ID supplies the name and root custom properties because workspace selection is sorted by ID, not click order. Surviving face materials, UVs and residual fields follow exact backend side ancestry. Equivalent support planes normally prefer the first operand; containment copies the containing operand's surfaces, and equal geometry takes the second operand's surfaces. Select and Block Tool Properties explain these constraints without changing the toolbar layout.
- Authored mesh integration now includes `map.brush.to_mesh`, `map.mesh.flip_normals` and `map.mesh.triangulate` in Objects/Groups. Conversion uses reconstructed brush boundaries, retains root and side-to-face identities, allocates fresh vertex IDs, and evaluates the original UV projections at each corner. Whole-mesh normals reversal and triangulation operate through the persistent source modeling transaction. Triangulation preserves corner surfacing and explicit parent-face metadata; completed triangle selections disable its command. These are whole-root actions, not enabled vertex/edge/face mesh editing. The validated mesh continuation below records the adapters, contextual shortcut policy and limits.
- Delete and duplication operate on supported geometry and authored entities. Rotation/scale do not approximate terrain or class-specific entity transforms using helper bounds.
- Faces 3, Objects 5 and Groups 6 are enabled. Vertices, edges and editable-mesh component commands still require their own selection/edit adapters.

Primitive preview generation uses a small private construction document with the live map's geometry policy. It validates the primitive and builds its wireframe without cloning or mutating the live map and without recording history. `editPreviewWire` is shared by the panes and cached by construction bounds and primitive configuration. Document publication, document adoption and gesture cancellation clear that cache. A failed preview is visibly invalid and never substitutes an earlier shape as a valid result.

Construction dimensions follow the live bounds in every pane and in Mason's status bar. X/Y/Z guides use the axis colors; the active pane also reports the current move offset, scale factors, rotation or face push/pull distance. Shift+wheel changes the gesture's omitted-axis depth by the live grid step; Ctrl/Command+Shift+wheel uses one world unit. These depth changes do not overwrite persistent creation defaults or add history. Keyboard confirmation commits the last successful primitive descriptor shown in the preview, preserving its shape, axis, tessellation and UV density if defaults changed since the last pointer update. Preview, committed and selected-face polygons share camera near-plane and viewport clipping; transformed and construction edges use clipped segments. Dimension guides deliberately require complete projected edges so a clipped fragment does not supply a misleading dimension guide.

Tool Properties' Confirm/Cancel rows use the effective contextual resolver, including user/platform remaps and inherited unbinding shadows. Identical 2D/3D bindings share a row; differing bindings are labeled by view family. The cutter picker caches document identity, selection/hidden revisions, visibility groups and cordon state; document notifications force invalidation. Preview and unrelated view updates preserve its model and chosen cutter without repeatedly scanning all brushes.

An edit validates on a private document, prepares its wireframe, registers owned history, and only then publishes. A drag produces one history step. Navigation, framing, resize, projection/FOV changes, tool/selection changes and focus loss cancel an active edit rather than reinterpreting its original cursor basis. Undo/redo prepare the destination before publishing; fixed before/after document snapshots preserve the ownership budget through saving and later selection changes. This is a correctness-first bridge to the existing geometry APIs. The persisted chunk inventory is tracked separately per destination, so undoing creation or moving across chunk cells cannot leave obsolete saved geometry to reappear on reload. If file replacement fails mid-save, the sink reports exactly which chunks were already published; retry cleanup includes those paths without claiming untouched files in another Save As destination. Recovery tracking capacity is reserved before any replacement. Large-map history should eventually use bounded source deltas, avoiding whole-document copies for every gesture.

The Claude handoff reports a full keybinding artifact; `/tmp/twist.keybindings` contains 825 entries across 53 contexts. It is a third-party mirror with no recorded installed Hammer version, so it is a discovery aid, not an authoritative default specification. In that artifact Ctrl+D means origin-to-pivot in ToolSelection and quad-slice in ToolFaceSelection. Mason's Ctrl+D duplicate is therefore a deliberate compatibility binding until component dispatch is complete. Do not call it Hammer 5's duplicate binding.

The Valve overview contains a duplicated Shift+P attribution (path and texture projection), and spans game versions. Exact parity should be checked against a versioned installed `hammer_key_bindings.txt`, not inferred from command names alone. A shortcut inventory exposes editor commands; it does not supply their algorithms or runtime dependencies.

Geometry authoring, asset inspection and document editing can progress now. Gameplay entity definitions/IO, audio audition, physics simulation, final lighting/render preview, runtime triggers/sequences and navigation generation need their corresponding engine systems before the UI can offer functional behavior. Keep unsupported commands visibly unavailable instead of faking an effect.

The complete unversioned binding discovery is preserved in [the CSV inventory](mason_hammer_binding_discovery.csv), with geometry and viewport contexts grouped in [the geometry inventory](mason_geometry_binding_inventory.md). These files preserve evidence; they do not activate unsupported commands.

Wireframe preparation propagates allocation failures for every supported geometry family and never publishes partially built faces. Authored brush polygons retain their complete corner rings, including faces above 64 corners. Allocation sweeps cover brushes, meshes, patches and terrain, with successful retries and audited cleanup.
